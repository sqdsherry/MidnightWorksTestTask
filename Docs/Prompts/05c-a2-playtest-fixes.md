## 2. Кладовщик: возврат «домой», порог «≤ 5» и несколько кладовщиков

### 2.1 Возврат домой
После выгрузки кладовщик не остаётся на синем паде точки, а **идёт к своему месту у склада** и ждёт там, пока не понадобится снова.
- Новая цель `StaffDestinationKind.Home` (место ожидания кладовщика у склада).
- Новое состояние `StaffState.ReturningHome`: после доставки → `MoveTo(Home)` → `Arrived` → `Idle`.
- Если пока он идёт домой появилась голодная точка — сразу разворачивается к складу (`ReturningHome → ToWarehouse`), не доходя до дома.
- В `LocationLayout` новое поле `_storekeeperSpots` (`Transform[]`, по одному на кладовщика, порядок = порядок найма). Setup-утилита создаёт **3** точки в ряд вдоль южной стены склада, с шагом 1.2 м, лицом от склада. Валидация: не меньше `MaxStorekeepers`.

### 2.2 Порог «5 и меньше»
Сейчас условие `Fill01 < RestockThreshold` (0.5) → при 5/10 кладовщик не идёт, идёт только с 4.
- Нужно: идёт, когда **запас ≤ 5** (вместе с уже несущимися ящиками).
- Сделать порог в **единицах**: `StaffSection._restockAtOrBelow` (int, по умолчанию 5) вместо доли; условие `Current + Incoming <= RestockAtOrBelow`. Старое поле `_restockThreshold` удалить (`Location1ConfigCreator` проставляет 5).
- Обновить тест границы: при 5/10 идёт, при 6/10 — нет.

### 2.3 Несколько кладовщиков
- На локацию можно нанять до `StaffSection._maxStorekeepers` (по умолчанию **3**).
- Цена n-го: `PriceFormula.Evaluate(StorekeeperCost, _storekeeperCostGrowth, n)`, где n — сколько уже нанято (600 → 900 → 1350 при росте 1.5).
- `IStaffService`:
  - `GetStorekeeperAvailability(locationId)` → `Hired` только когда достигнут максимум;
  - `GetStorekeeperCost` — цена следующего;
  - `int StorekeeperCount(locationId)`.
- Разные кладовщики не идут в одну и ту же точку: голодную точку выбирать с учётом `Incoming`, как сейчас. Если два кладовщика Idle в одном тике, второй увидит incoming первого и выберет другую точку или останется ждать.
- Сейв: `SaveData.storekeeperLocationIds` хранит id локации **по разу на каждого кладовщика**. `RestoreStorekeeper(locationId)` добавляет одного, до максимума. Обновить XML-доку.
- Панель склада (`StorekeeperOfferPresenter`):
  - заголовок со счётчиком «Storekeepers 1/3» (формат — поле view);
  - кнопка «Hire Storekeeper $900»;
  - при максимуме — «Max staff» (поле view);
  - после найма панель не закрывается, а обновляется к следующему.
- Каждый следующий кладовщик спавнится в комнате персонала и идёт к своему `_storekeeperSpots[i]`.

### Тесты
- После доставки: `ReturningHome` → `Arrived` → `Idle`.
- `ReturningHome` + голодная точка → `ToWarehouse` без захода домой.
- Порог: 5/10 → идёт, 6/10 → нет.
- Два кладовщика и две голодные точки → идут в разные. Одна голодная точка → идёт только один.
- Цена 2-го и 3-го по формуле. После 3-го → `Hired` (максимум), `TryHire` → false.
- `RestoreStorekeeper` трижды → 3 кладовщика, четвёртый игнорируется.
